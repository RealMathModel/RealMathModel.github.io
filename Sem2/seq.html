the whole idea

State is memory. The clock is the heartbeat.

A combinational circuit is a function: same inputs → same output, instantly. Add a flip-flop and the circuit gains a present state — so the same input can do different things depending on what came before. The clock decides when state is allowed to change.

Combinational
output = f(inputs)

No memory. A full adder always gives the same SUM for the same A, B, Cin. Chapters 1–4 lived here.

Y = f(X)
Sequential
output = f(inputs, present state)

Has memory in flip-flops. The next state is computed now but only latched on the clock edge. Chapters 5–6 live here.

Y = f(X, Q)  ·  Qnext = g(X, Q)

edge triggering

The edge is the moment.

An edge-triggered flip-flop samples its input only at the instant the clock rises (▲). Between edges the input can wiggle all it wants — nothing latches. Move the input line and watch: the output only steps at the rising edges.

▲ rising edge = sample Q follows D at the edge
the clocked loop

A feedback loop, broken by the clock.

This is what makes it sequential. The stored state is always fed back to the logic, which is always computing the next inputs. But nothing moves through the flip-flops until the edge — then everything latches at once. Watch one lap: read state → compute → edge latches → new state → repeat.

present state feeds back continuouslyedge = everyone latches together
Why the break matters: wire an output straight back to its input with no flip-flop and you get a race — it spins or latches unpredictably. The flip-flop cuts the loop so signals only pass on the edge, turning a chaotic instant-loop into an orderly one-step-per-clock sequence. That's the whole idea of synchronous sequential logic.

design direction

Spec → circuit. Follow the recipe.

Design runs the other way: from a word problem to gates. The skeleton never changes — memorize the order like a recipe. Steps 5–6 are where your K-map skill and the excitation tables do the work.

State diagram / word spec. Translate the requirement into states and transitions.
State table. Present state + inputs → next state + outputs.
State reduction. Merge equivalent states so you don't build a bloated machine.
State assignment. Give each state a binary code → fixes how many flip-flops.
Excitation table. For each transition, look up the FF inputs (D, or J/K, or T…).
K-map each flip-flop input. Variables = all state bits and all external inputs. One map per input wire.
Draw the circuit. Wire the minimized input equations to the flip-flops.
The map-size rule. Every flip-flop input is a function of all present-state bits + all external inputs, so each K-map has (#flip-flops + #inputs) variables. And you draw one map per input wire: a D flip-flop has 1 input → 1 map; a JK has 2 (J and K) → 2 maps. Two JK flip-flops = four maps.

Turn any flip-flop into any other.

state reduction

Shrink the machine before you build it.

Two states are equivalent if, for every input, they give the same output and go to equivalent next-states. Merge them — fewer states means fewer flip-flops and less logic. This is Problem 5.12.

BEFORE — 5 states
Statenext x=0next x=1out
acd0
bcd0
cad0
dea1
ead0
AFTER — a≡b (same outputs, same next-states), c≡e
Statenext x=0next x=1out
acd0
cad0
dca1
5 → 3 states. b folds into a; e folds into c. A 5-state machine needs 3 flip-flops; a 3-state machine needs only 2.
How to find equivalents: group states by output first (only same-output states can be equivalent), then check their next-states land in the same groups. Repeat until groups stop splitting — that's the implication-table method in a nutshell.
unused states

Don't-cares that can bite.

With 3 flip-flops you get 8 states — but a design might only use 5 or 6. The leftovers become don't-cares in your K-maps (great — they simplify the logic). But you must verify the machine can't get stuck in one. This is Problem 5.19 / 6.24.

Mark unused state codes as X in every flip-flop-input K-map — they shrink your groups for free.
Finish the design with those don't-cares included.
Now go backward: plug each unused code into your final equations and compute where it actually goes.
Check it re-enters the valid cycle. If an unused state maps to another unused state that loops forever, the counter is stuck — you must fix the design (force unused states to a known valid state).
The trap: treating unused states as don't-cares gives the simplest logic, but if the circuit powers up in one, it might never reach the intended sequence. Always trace the unused states through your final equations — the simplest design isn't always self-correcting.
CHAPTER 6 · counters
ripple vs synchronous

Same count. Very different timing.

Both counters reach the same value — but watch how. In the ripple (asynchronous) counter each flip-flop clocks the next, so the change crawls left-to-right like a wave. In the synchronous counter every flip-flop shares the clock and flips at once. Press the pulse and watch the difference.

Ripple counter asynchronous

FF0 clocks FF1 clocks FF2… — carry ripples with delay.
value 0 · propagation visible left→right

Synchronous counter one clock

Every flip-flop shares the clock — all bits update together.
value 0 · all bits latch on the same edge
Why it matters: ripple is simpler to wire but its worst-case delay stacks up — n × tpd for n flip-flops — which caps the clock frequency (Problem 6.15). Synchronous costs more logic but every output settles together, so it runs faster and cleaner. That trade is the heart of Chapter 6.

ripple timing

How fast can a ripple counter run?

In a ripple counter the carry has to propagate through every flip-flop in the worst case (e.g. 0111→1000 flips all four). Total delay = n × tpd, and the counter can't be clocked faster than that. This is Problem 6.15 — set the values and see.

n = 10
3 ns
max delay = n × tpd = 30 ns
fmax = 1 / delay = 33.3 MHz
Contrast: a synchronous counter's max delay is just one flip-flop plus the carry logic — it doesn't grow with n the way ripple does. That's the whole reason synchronous counters exist.
serial arithmetic

Registers that compute one bit at a time.

Chapter 6's serial adder and serial 2's-complementer (Problems 6.8, 6.10, 6.17) are shift registers with a tiny state machine attached. They trade speed for gate count — one bit per clock instead of all at once.

Serial adder

Two shift registers feed a full adder one bit-pair per clock. The carry is stored in a flip-flop and fed back — so the "state" is literally the carry. Sum bits shift back into register A. After n clocks, A holds the sum.

state = carry FF ·   S = A⊕B⊕Cin,   Cout stored
Serial 2's complementer

Scan from the LSB: copy bits up to and including the first 1, then complement the rest. That "have we passed the first 1 yet?" is a one-bit state — a 2-state machine driving an XOR. Exactly Problem 5.17 / 6.10.

2 states: "before first 1" (copy) · "after" (invert)

the four modes

SISO, SIPO, PISO, PIPO — how data gets in and out.

A shift register is classified by how data enters (serially, one bit per clock, or in parallel, all at once) and how it leaves. That's two choices × two = four modes. Teal = serial (one wire, n clocks); amber = parallel (n wires, one clock).

SISO serial-in, serial-out

Use: delay line / time buffer — a bit that goes in comes out n clocks later. Pure serial data movement.

SIPO serial-in, parallel-out

Use: serial→parallel conversion — a receiver clocks bits in one at a time, then reads the whole word at once.

PISO parallel-in, serial-out

Use: parallel→serial conversion — a transmitter loads a word in one clock, then shifts it out bit by bit onto one line.

PIPO parallel-in, parallel-out

Use: a plain storage register / buffer — load all bits, read all bits. No shifting needed to move data.

Universal shift register 6.7
Does everything, chosen by a 2-bit mode control (s₁s₀).
s₁ s₀operation
0 0hold (no change)
0 1shift right
1 0shift left
1 1parallel load
How it's built: put a 4×1 MUX in front of each flip-flop's D input, selected by s₁s₀. The four data lines are: the FF's own output (hold), the right neighbour (shift right), the left neighbour (shift left), and the external parallel bit (load). One MUX per bit = a register that can do all four modes.

circular counters

Ring & Johnson: shift registers that eat their own tail.

Feed a shift register's output back to its input and it counts by circulating a pattern. A ring counter walks a single 1 around (n states). A Johnson counter feeds back the inverted output, doubling the count to 2n states. Auto-run them and watch the patterns cycle.

Ring counter n states
One hot bit circulates: 1000 → 0100 → 0010 → 0001 → …
Johnson counter 2n states
Inverted feedback fills then empties: 0000→1000→1100→1110→1111→0111→…
Count the states: with 4 flip-flops a ring counter gives 4 states, a Johnson counter gives 8 = 2n (Problem 6.30). That's why Johnson counters are a cheap way to double your count without adding flip-flops.
mod-N

Any modulus: count, detect, reset.

A binary counter naturally counts to 2ⁿ. To make a mod-N counter you detect the moment the count hits N and force it back to 0. Drag the slider to set N and run it — the counter loops through exactly N states.

The recipe (Problem 6.22): a mod-N counter = a binary counter + a detector for state N-1 (or N) wired to the load, clear, or carry input. A NAND gate that fires on the terminal count and clears the flip-flops is the classic BCD (mod-10) trick.
know it or not

The definitions, stated plainly.

These are the "define this / true or false" exam points — the ones no problem drills. Be able to say each, not just use it.

Moore vs Mealy

Moore: output depends on the present state only — output is glitch-free and changes only on the clock. Mealy: output depends on state and current input — reacts one clock sooner and often needs fewer states, but its output can change mid-cycle.

Synchronous vs asynchronous

Synchronous: every flip-flop shares one common clock — all update together. Asynchronous (ripple): a flip-flop's clock comes from another flip-flop's output, so changes propagate with delay. Synchronous is faster and race-free; ripple is simpler but slower.

Latch vs flip-flop

Latch: level-sensitive — transparent whenever the enable is active, so the output tracks the input during that whole level. Flip-flop: edge-triggered — samples only at the clock edge. Flip-flops are what you build synchronous machines from.

Master–slave

Two latches in series with opposite clock phases. The master captures while the clock is high; the slave passes it out when the clock goes low. Net effect: the flip-flop behaves as if it captured on one edge and is immune to input changes during the active level (avoids the "ones-catching" problem).

Setup & hold time

The data input must be stable for a setup window before the clock edge and a hold window after it. Violate either and the flip-flop can go metastable — settling to an unpredictable value.

State equivalence

Two states are equivalent if, for every input, they produce the same output and transition to equivalent next-states. Equivalent states can be merged — that's state reduction, and it cuts the flip-flop count.

Characteristic vs excitation

Characteristic: inputs → Qnext (used in analysis). Excitation: desired Q → Qnext → required inputs (used in design). Inverse views of the same flip-flop.

Register vs counter

A register is a group of flip-flops that store/shift a word. A counter is a register whose state advances through a fixed sequence on each clock. Every counter is a state machine; not every register counts.
